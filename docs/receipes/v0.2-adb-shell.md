# v0.2 Recipe: ADB Shell

This recipe adds a reusable Python wrapper for commands executed by `adb shell`, then uses it to
inspect a connected Android device.

## Goal

The v0.2 implementation can:

- target one device by serial;
- execute a shell command from separate argument tokens;
- retain readable command text and output in `ShellResult`;
- read the current user, working directory, and kernel information;
- parse entries returned by `ls /`; and
- test helpers with mocks and a real-device integration suite.

## Prerequisites

Complete the [environment setup](../environment.md) and
[v0.1 ADB basics](v0.1-adb-basics.md), then confirm that a device is online:

```bash
adb devices -l
```

## 1. Run a device shell command

The underlying ADB form is:

```bash
adb -s emulator-5554 shell uname -a
```

Replace the example serial with one reported by `adb devices`. Explicit `-s` targeting avoids
ambiguity when multiple devices are connected.

## 2. Wrap shell execution

`run_shell()` in `src/android_cookbook/shell.py` reuses the v0.1 `run_adb()` boundary:

```python
def run_shell(serial: str, *command: str) -> ShellResult:
    output = run_adb("-s", serial, "shell", *command)
    return ShellResult(command=" ".join(command), output=output)
```

Callers pass every command token separately:

```python
result = run_shell("emulator-5554", "uname", "-a")
```

This returns a value shaped like:

```python
ShellResult(command="uname -a", output="Linux ...")
```

`ShellResult` is immutable. Its `command` is a readable representation; execution uses the
original argument list through `subprocess.run`, without `shell=True`.

## 3. Add focused helpers

| Helper | Device command | Return value |
| --- | --- | --- |
| `get_working_directory(serial)` | `pwd` | stripped string |
| `get_current_user(serial)` | `whoami` | stripped string |
| `get_kernel_info(serial)` | `uname -a` | stripped string |
| `list_root_directory(serial)` | `ls /` | non-empty, stripped lines as `list[str]` |

`run_adb()` initially strips output. `list_root_directory()` additionally splits it into lines and
removes blank entries. `ProcessInfo(user, pid, name)` is defined for future process parsing, but
the current workflow does not use it.

## 4. Print shell information

```bash
PYTHONPATH=src poetry run python -m android_cookbook.shell_info
```

The module selects the first device whose state is `device` and is intended to print:

```json
{
  "serial": "emulator-5554",
  "user": "shell",
  "cwd": "/",
  "kernel": "Linux localhost 6.1.0-android ...",
  "root_directories": ["system", "vendor", "data"]
}
```

If no online device exists, it raises `RuntimeError: No Android device available`.

> Known source-code issue: `shell_info.py` currently calls `get_kernel_info()` for `cwd`, so the
> actual value duplicates `kernel`. Calling `get_working_directory(serial)` there will make output
> match the example.

## 5. Test the shell boundary

Unit tests replace `android_cookbook.shell.run_adb`, so they require no device:

```bash
poetry run pytest tests/unit/test_shell.py -v
```

They verify the ADB argument tuple, returned `ShellResult`, user and working-directory output, and
root-list parsing.

Integration tests execute real ADB commands:

```bash
poetry run pytest tests/integration/test_shell.py -m integration -v
```

They check that `whoami` is non-empty, `uname -a` contains `Linux`, and `ls /` includes `system`.
They skip when no online device is available.

## Troubleshooting

### A command raises `CalledProcessError`

`run_adb()` uses `check=True`, so a non-zero status propagates. Run the equivalent ADB command
directly to inspect stderr and confirm the device is online and authorized.

### Integration tests are skipped

Run `adb devices -l` and confirm that a row has state `device`. `offline` and `unauthorized` are
not eligible.
