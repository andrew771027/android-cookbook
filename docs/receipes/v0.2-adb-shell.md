# v0.2 Recipe: ADB Shell

This recipe adds a reusable Python wrapper for commands executed by `adb shell`, then uses it to
inspect a connected Android device.

## Goal

The v0.2 implementation can:

- target one device by serial;
- execute a shell command from separate argument tokens;
- retain readable command text and output in `ShellResult`;
- read the current user, working directory, and kernel information;
- parse entries returned by `ls /`; and
- test helpers with mocks and a real-device integration suite.

## Prerequisites

Complete the [environment setup](../environment.md) and
[v0.1 ADB basics](v0.1-adb-basics.md), then confirm that a device is online:

```bash
adb devices -l
```

## 1. Run a device shell command

The underlying ADB form is:

```bash
adb -s emulator-5554 shell uname -a
```

Replace the example serial with one reported by `adb devices`. Explicit `-s` targeting avoids
ambiguity when multiple devices are connected.

## 2. Wrap shell execution

`run_shell()` in `src/android_cookbook/shell.py` reuses the v0.1 `run_adb()` boundary:

```python
def run_shell(serial: str, *command: str) -> ShellResult:
    output = run_adb("-s", serial, "shell", *command)
    return ShellResult(command=" ".join(command), output=output)
```

Callers pass every command token separately:

```python
result = run_shell("emulator-5554", "uname", "-a")
```

This returns a value shaped like:

```python
ShellResult(command="uname -a", output="Linux ...")
```

`ShellResult` is immutable. Its `command` is a readable representation; execution uses the
original argument list through `subprocess.run`, without `shell=True`.

## 3. Add focused helpers

| Helper | Device command | Return value |
| --- | --- | --- |
| `get_working_directory(serial)` | `pwd` | stripped string |
| `get_current_user(serial)` | `whoami` | stripped string |
| `get_kernel_info(serial)` | `uname -a` | stripped string |
| `list_root_directory(serial)` | `ls /` | non-empty, stripped lines as `list[str]` |

`run_adb()` initially strips output. `list_root_directory()` additionally splits it into lines and
removes blank entries. `ProcessInfo(user, pid, name)` is defined for future process parsing, but
the current workflow does not use it.

## 4. Explore the Android shell

The following read-only commands are useful for learning what runs on an Android device. When
only one device is connected, the short `adb shell ...` form is sufficient. With multiple
devices, add `-s <serial>` before `shell`.

### Identify the shell user

```bash
adb shell whoami
adb shell id
```

`whoami` prints only the current user name, which is usually `shell` for a normal ADB session.
`id` provides more detail: the numeric user ID (UID), primary group ID (GID), supplementary
groups, and usually the SELinux security context. A typical non-root result resembles:

```text
shell
uid=2000(shell) gid=2000(shell) groups=... context=u:r:shell:s0
```

The exact groups and context vary by Android version and device. A production device normally
does not grant the ADB shell unrestricted root access.

### Discover Toybox commands

```bash
adb shell toybox
```

Toybox is the compact command-line toolkit included with Android. One executable provides many
standard Unix-like commands—often called applets—such as `cat`, `df`, `id`, `ls`, `ps`, `pwd`,
`tr`, `uname`, and `whoami`. Running `toybox` without an applet prints the commands supported by
that device's Android build.

An applet can also be invoked through Toybox explicitly:

```bash
adb shell toybox uname -a
adb shell toybox ps -A
```

In normal use, `adb shell uname -a` and `adb shell ps -A` usually resolve to the corresponding
Toybox applets automatically. The explicit form is useful when confirming which implementation
is being used. Available applets and supported options can vary by Android/Toybox version.

To display help for one applet:

```bash
adb shell toybox --help ps
```

### Inspect the kernel

```bash
adb shell uname -a
```

`uname -a` prints kernel information such as the kernel name, device hostname, release, build
version, and CPU architecture. Android uses the Linux kernel, so the output normally begins with
`Linux`. This command is the basis of `get_kernel_info()`.

### List running processes

```bash
adb shell ps -A
```

`ps -A` lists all processes visible to the ADB shell. Depending on the Android/Toybox version,
columns commonly include the process user, PID, parent PID, state, and process name. Useful names
to look for include `init`, `system_server`, `surfaceflinger`, and application package processes.

To inspect a smaller result, combine it with a filter on the device:

```bash
adb shell "ps -A | grep system_server"
```

The quotes ensure that the pipe and `grep` execute on the Android device rather than on the host.

The current `ProcessInfo` dataclass is a starting point for a future parser, but v0.2 does not yet
parse `ps` output because its columns can vary between Android versions.

### Inspect Android's first process

```bash
adb shell cat /proc/1/cmdline
```

PID 1 is Android's first userspace process and is normally `init`. The virtual file
`/proc/1/cmdline` stores command-line arguments separated by NUL bytes rather than normal line
breaks, so the result may appear as `init` without a trailing newline. For readable separators:

```bash
adb shell "cat /proc/1/cmdline | tr '\\0' ' '"
```

Quoting makes the pipe run in the device shell. Access to some other processes under `/proc` may
be restricted by Android permissions and SELinux even when `/proc/1/cmdline` is readable.

### Inspect memory information

```bash
adb shell cat /proc/meminfo
```

`/proc/meminfo` exposes kernel memory counters, normally in KiB. Important fields include:

- `MemTotal`: total usable physical memory;
- `MemFree`: completely unused memory;
- `MemAvailable`: kernel estimate of memory available without heavy swapping;
- `Buffers` and `Cached`: memory used for filesystem buffering and caches; and
- `SwapTotal` and `SwapFree`: configured and unused swap space.

On modern systems, `MemAvailable` is usually more meaningful than `MemFree` when estimating
available memory.

### Inspect filesystem capacity

```bash
adb shell df -h
```

`df` reports mounted filesystems and their used and available space. `-h` formats sizes in units
such as MiB and GiB. Useful mount points commonly include `/system`, `/data`, `/vendor`, and
`/storage`, although dynamic partitions and device-specific layouts can change what appears.
`/data` is usually the most relevant filesystem when investigating space used by apps and user
data.

### Explore important directories

```bash
adb shell ls /
adb shell ls /system
adb shell ls /data
adb shell ls /proc
```

Each command answers a different question:

| Path | What it represents |
| --- | --- |
| `/` | Android's root filesystem and top-level mount points |
| `/system` | Core Android framework, libraries, binaries, and system files |
| `/data` | Writable application and user data; many children are permission-restricted |
| `/proc` | Virtual, kernel-generated process and system information |

`ls /` is wrapped by `list_root_directory()`. `/proc` is not stored on disk: numeric entries such
as `/proc/1` represent processes, while files such as `/proc/meminfo` expose live kernel state.
On a non-root production device, `ls /data` may show limited entries or return
`Permission denied`; this is expected security behavior rather than an ADB connection failure.

## 5. Print shell information

```bash
PYTHONPATH=src poetry run python -m android_cookbook.shell_info
```

The module selects the first device whose state is `device` and is intended to print:

```json
{
  "serial": "emulator-5554",
  "user": "shell",
  "cwd": "/",
  "kernel": "Linux localhost 6.1.0-android ...",
  "root_directories": ["system", "vendor", "data"]
}
```

If no online device exists, it raises `RuntimeError: No Android device available`.

> Known source-code issue: `shell_info.py` currently calls `get_kernel_info()` for `cwd`, so the
> actual value duplicates `kernel`. Calling `get_working_directory(serial)` there will make output
> match the example.

## 6. Test the shell boundary

Unit tests replace `android_cookbook.shell.run_adb`, so they require no device:

```bash
poetry run pytest tests/unit/test_shell.py -v
```

They verify the ADB argument tuple, returned `ShellResult`, user and working-directory output, and
root-list parsing.

Integration tests execute real ADB commands:

```bash
poetry run pytest tests/integration/test_shell.py -m integration -v
```

They check that `whoami` is non-empty, `uname -a` contains `Linux`, and `ls /` includes `system`.
They skip when no online device is available.

## Troubleshooting

### A command raises `CalledProcessError`

`run_adb()` uses `check=True`, so a non-zero status propagates. Run the equivalent ADB command
directly to inspect stderr and confirm the device is online and authorized.

### Integration tests are skipped

Run `adb devices -l` and confirm that a row has state `device`. `offline` and `unauthorized` are
not eligible.
