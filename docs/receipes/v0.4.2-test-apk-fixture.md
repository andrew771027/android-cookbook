# Android Cookbook v0.4.2 — Test APK Fixture

## Goal

Provide a minimal, reproducible Android APK used exclusively by Android Cookbook integration tests.

The fixture exists to support Package Manager lifecycle testing:

```text
Build
  |
  v
APK
  |
  | install
  v
Installed Package
  |
  | clear
  v
Installed Package / Clean Data
  |
  | uninstall
  v
Removed
```

The fixture is not a production Android application.

It intentionally contains no Activity, UI, business logic, network access, or application permissions.

---

## Package Identity

```text
com.example.androidcookbook.fixture
```

The package name must remain stable because integration tests use it as the expected package identity.

## Build the test APK

This guide takes you from tool installation to an APK ready for integration tests.
The commands use Bash or Zsh. Start from the repository root unless a step changes
into `fixtures/test-app`.

### 1. Prepare Java and the Android build tools

| Tool | Version | Purpose |
| --- | --- | --- |
| JDK | 17 | Runs Gradle and the Android build plugin |
| Gradle | 9.3.1 | Builds the fixture and generates the Gradle Wrapper |
| Android SDK Platform | 36 | Provides the Android APIs used to compile the app |
| Android SDK Build Tools | 36.0.0 | Packages the compiled app into an APK |
| Android SDK Platform Tools | Provided by Android Environment | Provides ADB for device validation |

The fixture uses Android Gradle Plugin 9.1.1. See its
[compatibility requirements](https://developer.android.com/build/releases/agp-9-1-0-release-notes)
for the required Gradle, JDK, and Build Tools versions.

Use the SDK and build tools from Android Environment, which also provides the
emulator runtime used by the Cookbook. Make sure that SDK installation includes
Platform 36 and Build Tools 36.0.0. If they are missing, install them through that
environment's SDK setup or Android Studio's SDK Manager.
An emulator is needed for device validation, but does not need to run during the build.

On macOS, install [Temurin JDK 17](https://adoptium.net/temurin/releases/?version=17)
using the macOS `.pkg` installer. Choose **x64** for Intel Macs or **aarch64** for
Apple Silicon. Configure Java in the current terminal:

```bash
export JAVA_HOME=$(/usr/libexec/java_home -v 17)
export PATH="$JAVA_HOME/bin:$PATH"
java -version
```

On Linux, install JDK 17 and set `JAVA_HOME` to its installation directory.

### 2. Install Gradle

Choose one installation method. The project uses Gradle 9.3.1; the ZIP method
below installs that version explicitly.

#### macOS: Homebrew

```bash
brew install gradle
gradle --version
```

Homebrew may install a newer Gradle and its own JDK dependency. Use the ZIP method
if you need Gradle 9.3.1 or if the OpenJDK dependency fails to install.

#### macOS: bypass Homebrew with the Gradle ZIP

If Homebrew reports `Xcode alone is not sufficient on Tahoe`, use the prebuilt
JDK from step 1 and download Gradle directly. This avoids compiling Homebrew's
OpenJDK dependency, including on Intel Macs without supported bottles.

```bash
mkdir -p "$HOME/.local/gradle"
curl -fL https://services.gradle.org/distributions/gradle-9.3.1-bin.zip \
  -o /tmp/gradle-9.3.1-bin.zip
unzip -q /tmp/gradle-9.3.1-bin.zip -d "$HOME/.local/gradle"

export PATH="$HOME/.local/gradle/gradle-9.3.1/bin:$PATH"
gradle --version
```

The version output should show Gradle 9.3.1 and Java 17. If you already extracted
the ZIP, reuse that directory and run the `export` command.
To keep the Java and Gradle settings in new terminals, add the three `export`
lines from steps 1 and 2 to `~/.zshrc` (Zsh) or `~/.bash_profile` (Bash).

#### Linux: SDKMAN!

Install JDK 17 first. Ensure `curl`, `zip`, and `unzip` are available, then install
Gradle with [SDKMAN!](https://sdkman.io/install/):

```bash
curl -s "https://get.sdkman.io" | bash
source "$HOME/.sdkman/bin/sdkman-init.sh"
sdk install gradle 9.3.1
gradle --version
```

See the [Gradle installation guide](https://gradle.org/install/)
for other installation methods.

### 3. Point Gradle to the Android Environment SDK

Set `ANDROID_HOME` to the SDK directory used by Android Environment. The example
below uses the default macOS SDK location; replace it if your SDK is elsewhere.
On Linux, the usual location is `$HOME/Android/Sdk`.

```bash
export ANDROID_HOME="$HOME/Library/Android/sdk"
export PATH="$ANDROID_HOME/platform-tools:$PATH"

ls "$ANDROID_HOME/platforms/android-36/android.jar"
ls "$ANDROID_HOME/build-tools/36.0.0"
```

Both paths must exist before you build. If either is missing, return to step 1
and install the corresponding SDK component. See
[Set up your environment](../environment.md) for ADB and emulator setup.

### 4. Prepare the Gradle Wrapper

From the repository root, enter the fixture project:

```bash
cd fixtures/test-app
```

The Wrapper needs `gradlew`, `gradlew.bat`, `gradle/wrapper/gradle-wrapper.jar`, and
`gradle/wrapper/gradle-wrapper.properties`. If any of these files are missing,
generate them with the installed Gradle:

```bash
gradle wrapper --gradle-version 9.3.1
```

Verify the Wrapper:

```bash
./gradlew --version
```

It should report Gradle 9.3.1. The first run downloads the Gradle distribution.
Use `./gradlew` for subsequent builds so the project uses its configured version.

### 5. Build the debug APK

While still in `fixtures/test-app`, run:

```bash
./gradlew assembleDebug
```

The first build downloads dependencies. When it finishes with `BUILD SUCCESSFUL`,
the debug APK is available at:

```text
fixtures/test-app/app/build/outputs/apk/debug/app-debug.apk
```

### 6. Prepare the integration test artifact

Return to the repository root and run the build script:

```bash
cd ../..
./scripts/build-test-apk.sh
```

The script runs `./gradlew assembleDebug` inside the fixture project and copies
the APK to the path used by integration tests:

```text
tests/fixtures/test-app/cookbook-test-app.apk
```

After the initial setup, run `./scripts/build-test-apk.sh` from the repository
root whenever you need to rebuild and copy the APK. You can skip the separate
build in step 5 when using this script.

## Manual Validation

Verify the Android runtime:

```bash
adb devices
```

Install:

```bash
adb -s emulator-5554 install -t \
  tests/fixtures/test-app/cookbook-test-app.apk
```

A streamed installation returns:

```text
Performing Streamed Install
Success
```

The `-t` option permits installation of a test-only APK. Replace `emulator-5554`
with the serial shown by `adb devices`; the device must run API 31 or later.

Verify:

```bash
adb -s emulator-5554 shell \
  pm list packages \
  com.example.androidcookbook.fixture
```

Expected:

```text
package:com.example.androidcookbook.fixture
```

Find the APK:

```bash
adb -s emulator-5554 shell \
  pm path \
  com.example.androidcookbook.fixture
```

Clear application data:

```bash
adb -s emulator-5554 shell \
  pm clear \
  com.example.androidcookbook.fixture
```

Verify that the package remains installed.

Finally:

```bash
adb -s emulator-5554 uninstall \
  com.example.androidcookbook.fixture
```

Verify that the package no longer exists.

The fixture build and lifecycle execution remain separate responsibilities.

## Test Execution

Build the fixture first:

```bash
./scripts/build-test-apk.sh
```

Then run:

```bash
PYTHONPATH=src poetry run pytest \
  tests/integration/test_package_lifecycle.py \
  tests/integration/test_package_lifecycle_state_machine.py \
  -v
```

The lifecycle test must leave the Android environment clean even when a test fails.

---

## Scope

v0.4.2 covers only Package Manager testing.

The fixture intentionally does not contain:

- Activity
- UI
- Service
- BroadcastReceiver
- database
- SharedPreferences
- network behavior
- application permissions

Application runtime behavior belongs to later Android Cookbook versions.

---

## Done Definition

v0.4.2 is complete when:

- the fixture Android project builds successfully
- a valid APK is generated
- the APK installs on the Android Environment emulator
- the expected package appears in Package Manager
- `pm path` resolves the installed APK
- `pm clear` succeeds without uninstalling the package
- `adb uninstall` removes the package
- v0.4.1 Package Lifecycle Integration passes
- cleanup leaves the emulator without the fixture package
