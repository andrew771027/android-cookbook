# v0.4.2: Test APK fixture

Build a minimal, reproducible Android APK for Android Cookbook integration tests,
validate its Package Manager lifecycle, and prepare the artifact used by
[Package lifecycle (v0.4.1)](v0.4.1-package-lifecycle.md).

## Prerequisites

Complete the [environment setup](../environment.md). Run commands from the repository
root unless a step changes into `fixtures/test-app`; examples use Bash or Zsh.
The build requires JDK 17, the checked-in Gradle 9.3.1 Wrapper, Android SDK Platform 36, and Build Tools
36.0.0. The build steps below cover their setup.

For validation and integration tests, use a dedicated online emulator running API 31
or later. Confirm its serial with `adb devices -l` and replace `emulator-5554` in the
examples. An emulator does not need to run during the APK build.
The validation commands install the fixture, clear its data, and uninstall it.

## Understand the fixture

The fixture exists to support Package Manager lifecycle testing:

```text
Build
  |
  v
APK
  |
  | install
  v
Installed Package
  |
  | clear
  v
Installed Package / Clean Data
  |
  | uninstall
  v
Removed
```

The fixture is not a production Android application.

The original v0.4.2 fixture had no Activity or UI. In v0.5.0, it exports `.MainActivity`
and displays a text label for [Activity Manager testing](v0.5.0-activity-manager.md).
In v0.5.1, it logs lifecycle callbacks with an instance UUID and supports a graceful
finish request for [Activity lifecycle testing](v0.5.1-activity-lifecycle.md).
In v0.5.2, it adds a counter, saved instance state, and `CookbookState` logs for
[Activity recreation testing](v0.5.2-activity-recreation.md). `CookbookLifecycle` retains marker
`android-cookbook-v0.5.1`; `CookbookState` uses `android-cookbook-v0.5.2`.
It has no network behavior or application permissions.

The package name is `com.example.androidcookbook.fixture`. It must remain stable
because integration tests use it as the expected package identity.

The current fixture is version `0.5.4` (`versionCode = 6`). Its state logs include
`pid=<number>` for [process recovery](v0.5.3-process-death-recovery.md). The
[launch diagnostics tests](v0.5.4-activity-launch-diagnostics.md) use the same lifecycle
and state markers, graceful finish hook, and `report` action.

The fixture does not contain:

- Service
- BroadcastReceiver
- database
- SharedPreferences
- network behavior
- application permissions

See [Activity Manager (v0.5.0)](v0.5.0-activity-manager.md) for launch and process checks.

## Build the test APK

Follow these steps to produce the APK and copy it to the integration test path.

### 1. Prepare Java and the Android build tools

| Tool | Version | Purpose |
| --- | --- | --- |
| JDK | 17 | Runs Gradle and the Android build plugin |
| Gradle Wrapper | 9.3.1 | Downloads Gradle and runs the build |
| Android SDK Platform | 36 | Provides the Android APIs used to compile the app |
| Android SDK Build Tools | 36.0.0 | Packages the compiled app into an APK |
| Android SDK Platform Tools | Provided by Android Environment | Provides ADB for device validation |

The fixture uses Android Gradle Plugin 9.1.1. See its
[compatibility requirements](https://developer.android.com/build/releases/agp-9-1-0-release-notes)
for the required Gradle, JDK, and Build Tools versions.

Use the SDK and build tools from Android Environment, which also provides the
emulator runtime used by the Cookbook. Make sure that SDK installation includes
Platform 36 and Build Tools 36.0.0. If they are missing, install them through that
environment's SDK setup or Android Studio's SDK Manager.
An emulator is needed for device validation, but does not need to run during the build.

On macOS, install [Temurin JDK 17](https://adoptium.net/temurin/releases/?version=17)
using the macOS `.pkg` installer. Choose **x64** for Intel Macs or **aarch64** for
Apple Silicon. Configure Java in the current terminal:

```bash
export JAVA_HOME=$(/usr/libexec/java_home -v 17)
export PATH="$JAVA_HOME/bin:$PATH"
java -version
```

On Linux, install JDK 17 and set `JAVA_HOME` to its installation directory.

### 2. Point Gradle to the Android SDK

Set `ANDROID_HOME` to the SDK directory used by Android Environment. The example
below uses the default macOS SDK location; replace it if your SDK is elsewhere.
On Linux, the usual location is `$HOME/Android/Sdk`.

```bash
export ANDROID_HOME="$HOME/Library/Android/sdk"
export PATH="$ANDROID_HOME/platform-tools:$PATH"

ls "$ANDROID_HOME/platforms/android-36/android.jar"
ls "$ANDROID_HOME/build-tools/36.0.0"
```

Both paths must exist before you build. If either is missing, return to step 1
and install the corresponding SDK component. See
[Set up your environment](../environment.md) for ADB and emulator setup.

### 3. Verify the Gradle Wrapper

The repository includes the Wrapper scripts, JAR, and configuration. From the repository
root, run:

```bash
(cd fixtures/test-app && ./gradlew --version)
```

The Wrapper reports Gradle 9.3.1 and downloads that distribution on the first run.

### 4. Build the integration test artifact

From the repository root, run:

```bash
./scripts/build-test-apk.sh
```

The script runs `./gradlew assembleDebug` inside the fixture project and copies
`fixtures/test-app/app/build/outputs/apk/debug/app-debug.apk` to the path used by integration tests:

```text
tests/fixtures/test-app/cookbook-test-app.apk
```

After the initial setup, run `./scripts/build-test-apk.sh` from the repository
root whenever you need to rebuild and copy the APK. You can skip the separate
build in step 5 when using this script.

## Validate the package lifecycle

Verify the Android runtime:

```bash
adb devices
```

Install:

```bash
adb -s emulator-5554 install -t \
  tests/fixtures/test-app/cookbook-test-app.apk
```

A streamed installation returns:

```text
Performing Streamed Install
Success
```

The `-t` option permits installation of a test-only APK. Replace `emulator-5554`
with the serial shown by `adb devices`; the device must run API 31 or later.

Verify:

```bash
adb -s emulator-5554 shell \
  pm list packages \
  com.example.androidcookbook.fixture
```

Expected:

```text
package:com.example.androidcookbook.fixture
```

Find the APK:

```bash
adb -s emulator-5554 shell \
  pm path \
  com.example.androidcookbook.fixture
```

Clear application data:

```bash
adb -s emulator-5554 shell \
  pm clear \
  com.example.androidcookbook.fixture
```

Verify that the package remains installed.

Finally:

```bash
adb -s emulator-5554 uninstall \
  com.example.androidcookbook.fixture
```

Verify that the package no longer exists.

## Run the tests

The test commands in this recipe are targeted development checks. Before every
commit, follow the [full commit verification procedure](../../CommitManual.md#run-the-full-integration-suite):
rebuild the APK, run all unit tests and the entire integration suite (including
destructive tests), and require every test to pass without skips or deselection.
Use only a dedicated online emulator and run sequentially.

The fixture build provides the real APK required by v0.4.1. Building the APK and
running the lifecycle tests are separate steps. Build the fixture first:

```bash
./scripts/build-test-apk.sh
```

Then select a dedicated emulator and opt in to destructive tests:

```bash
export ANDROID_SERIAL=emulator-5554
PYTHONPATH=src poetry run pytest \
  tests/integration/test_fixutre_apk.py \
  tests/integration/test_package_lifecycle.py \
  tests/integration/test_package_lifecycle_state_machine.py \
  -m "integration and destructive" -v
```

The APK smoke test and fixed-sequence tests use `ANDROID_SERIAL` and require the
fixture package to be absent at setup. The state machine selects the first online
device and removes any existing fixture package during setup. Each suite attempts
cleanup after running.

## Troubleshooting

- Java or Gradle version mismatch: check `java -version` and `./gradlew --version`
  from `fixtures/test-app`, then verify `JAVA_HOME` and `PATH`.
- Android SDK not found or SDK components missing: check `ANDROID_HOME`, Platform 36,
  and Build Tools 36.0.0 as described in the build steps.
- Wrapper files missing: restore the checked-in files listed under Project Structure.
- Installation fails: rebuild the APK, use an emulator running API 31 or later,
  and pass `-t` when installing a test-only APK directly with ADB.
- Tests skip: confirm the APK exists at `tests/fixtures/test-app/cookbook-test-app.apk`
  and `ANDROID_SERIAL` selects an online dedicated emulator.
- Tests report an already installed fixture: remove the manual installation with
  `adb -s emulator-5554 uninstall com.example.androidcookbook.fixture` before rerunning.
