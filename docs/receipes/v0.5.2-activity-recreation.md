# v0.5.2: Recreate an Activity and restore state

Rotate the dedicated emulator from portrait to landscape and verify that a new
`MainActivity` instance restores its counter from a saved Bundle. This recipe uses
`activity_recreation.py`, the lifecycle helpers, and the v0.5.2 test APK.

## Before you begin

Follow [Environment setup](../environment.md) and [Build the test APK](v0.4.2-test-apk-fixture.md).
Use an unlocked, dedicated emulator where rotation 0 gives portrait and rotation 1
gives landscape. The fixture requires API 31 or later. Run from the repository root:

```bash
poetry install
./scripts/build-test-apk.sh
export ANDROID_SERIAL=emulator-5554
adb devices -l
adb -s "$ANDROID_SERIAL" get-state
adb -s "$ANDROID_SERIAL" shell pm list packages com.example.androidcookbook.fixture
```

The emulator must report `device`, and the fixture package must be absent. If a manual
installation remains, remove it before running the tests:

```bash
adb -s "$ANDROID_SERIAL" uninstall com.example.androidcookbook.fixture
```

These tests install and uninstall the fixture, clear shared Logcat, change the foreground
Activity, and modify system rotation settings. Run sequentially without other automation.

## Observe recreation

The fixture displays a counter and its current orientation. Each Activity instance gets
a UUID. A foreground singleTop Activity handles `cookbook_action=increment` and `report`
in `onNewIntent()`. `increment` increases the counter; `report` only logs its value.

During `onSaveInstanceState()`, the fixture saves `counter` in the Bundle and emits a
`saved` state event. A replacement instance reads that value in `onCreate()` and emits
`created` with `restored=true`. Only the `created` event reflects whether a Bundle was
received; other state events log `restored=false`.

Run the automated exercise, including installation and cleanup:

```bash
PYTHONPATH=src poetry run pytest tests/integration/test_activity_recreation.py \
  -m "integration and destructive" -v -rs
```

The first test launches in portrait with counter 0, increments five times, and rotates
to landscape. It checks a `saved` event from the old instance and restored counter 5 in
a different instance. It also observes the old instance's ordered `onPause`, `onStop`,
`onDestroy` callbacks and the new instance's `onCreate`, `onStart`, `onResume` callbacks.
The second test checks that rotation creates a new instance and leaves the package
installed. Both tests use the shared package cleanup and controlled rotation fixtures.

The installed APK path is `tests/fixtures/test-app/cookbook-test-app.apk`. For manual
inspection after installing and launching that APK, the equivalent action command is:

```bash
adb -s "$ANDROID_SERIAL" shell am start -W --activity-single-top \
  -n com.example.androidcookbook.fixture/.MainActivity \
  --es cookbook_action increment
adb -s "$ANDROID_SERIAL" logcat -d -s CookbookLifecycle:I CookbookState:I '*:S'
```

Illustrative state output after five increments and rotation (UUIDs vary):

```text
CookbookState: marker=android-cookbook-v0.5.2 instance=11111111-1111-1111-1111-111111111111 event=incremented counter=5 orientation=portrait restored=false
CookbookState: marker=android-cookbook-v0.5.2 instance=11111111-1111-1111-1111-111111111111 event=saved counter=5 orientation=portrait restored=false
CookbookState: marker=android-cookbook-v0.5.2 instance=22222222-2222-2222-2222-222222222222 event=created counter=5 orientation=landscape restored=true
```

Lifecycle callbacks use `CookbookLifecycle` with the same v0.5.2 marker. State saving
appears in `CookbookState`, rather than as an `onSaveInstanceState` lifecycle event.
The tests match lifecycle subsequences rather than requiring an exact combined ordering.

## Use the Python helpers

| Helper | Behavior |
| --- | --- |
| `parse_state_events(output)` | Parse state log lines into frozen `StateEvent` objects |
| `read_state_events(serial)` | Read and parse a filtered Logcat snapshot |
| `wait_for_state_event(serial, predicate)` | Return the first matching event; default timeout 15 seconds, polling interval 0.2 seconds |
| `capture_rotation_settings(serial)` | Capture `accelerometer_rotation` and `user_rotation`; absent keys become `None` |
| `set_user_rotation(serial, rotation)` | Disable automatic rotation and set rotation 0, 1, 2, or 3 |
| `restore_rotation_settings(serial, settings)` | Restore user rotation before automatic rotation; delete originally absent keys |
| `send_fixture_action(serial, action)` | Send `increment` or `report` to the fixture |
| `assert_state_restored(before, after)` | Require a different instance and orientation, equal counter, and restored state |

Capture rotation settings before changing them and restore them in `finally`, as the
integration fixture does. Remove a manual fixture installation after the exercise.
Restoration commands can fail; check cleanup errors and verify both settings afterward.
The tests attempt restoration but do not read the values back to assert cleanup success.

The parser requires the state tag and v0.5.2 marker, followed by instance, event, counter,
orientation, and restored fields in that order. It accepts nonnegative counters and
`portrait`, `landscape`, or `undefined` orientations. It does not validate full UUIDs
or restrict state event names beyond lowercase letters.

Polling searches each complete snapshot, so a predicate can match an older event.
Correlate by instance and counter to avoid stale matches. Negative timeouts and
nonpositive intervals raise `ValueError`. Timeout raises `LifecycleError`. ADB calls
share the lifecycle runner's 20-second timeout and can exceed the polling deadline.

## Verify changes

```bash
PYTHONPATH=src poetry run pytest tests/unit/test_activity_recreation.py -v
```

Unit tests cover parsing, unrelated logs, restoration invariants and failures, rotation
command construction, invalid rotation, setting capture and restoration, polling,
timeout, and increment action arguments. They do not exercise every setting validation
branch or prove that rotation settings were restored on a device.

Before committing, follow [Commit Manual](../../CommitManual.md): rebuild the APK, leave
only the dedicated emulator online, and run the complete unit and integration suites:

```bash
PYTHONPATH=src poetry run pytest tests/unit
PYTHONPATH=src poetry run pytest tests/integration -m integration -v -rs
git diff --check
```

All tests must pass without failures, errors, skips, or deselection. The targeted commands
in this recipe cover only part of that requirement. Confirm package absence and restored
rotation settings after teardown.

## Limits

This exercise verifies Activity instance replacement and transient counter restoration.
It does not assert process identity, test process death, or provide persistent storage.
Rotation behavior depends on the device and configuration. Logcat snapshots can lose
entries, and `onDestroy()` is not guaranteed during process death. No CLI is provided
for the recreation helpers.
