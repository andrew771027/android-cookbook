# Android Cookbook v0.5.2 — Activity Recreation / Configuration Change

## Overview

This recipe explores Android Activity recreation caused by configuration changes, using screen rotation as a controlled test scenario.

The goal is to validate that an Activity instance can be destroyed and recreated while preserving temporary UI state through `onSaveInstanceState()` and `savedInstanceState`.

## Prerequisites

- Android Environment v0.4.x
- Android Emulator with API 36
- Android Cookbook v0.5.1
- Updated v0.5.2 Test APK Fixture
- Python and pytest

## Key Concepts

### Activity Recreation

A configuration change may cause Android to destroy and recreate an Activity instance.

The application package remains installed, and the application process may remain alive.

### Configuration Change

Examples include:

- Screen orientation changes
- Locale changes
- Screen size changes
- UI mode changes

Not every configuration change causes recreation. Behavior depends on the Android version, Activity manifest configuration, and device environment.

### Saved Instance State

`onSaveInstanceState(Bundle)` stores small amounts of transient UI state.

During recreation, the saved Bundle can be supplied to `onCreate(Bundle)`.

Example:

```java
@Override
protected void onSaveInstanceState(Bundle outState) {
    outState.putInt("counter", counter);
    super.onSaveInstanceState(outState);
}
```

Restore:

```java
@Override
protected void onCreate(Bundle savedInstanceState) {
    super.onCreate(savedInstanceState);

    if (savedInstanceState != null) {
        counter = savedInstanceState.getInt("counter", 0);
    }
}
```

## Manual Exercise

Build:

```bash
./scripts/build-test-apk.sh
```

Install:

```bash
adb -s emulator-5554 install -r \
  tests/fixtures/cookbook-test-app.apk
```

Launch:

```bash
adb -s emulator-5554 shell am start -S -W \
  -n com.example.androidcookbook.fixture/.MainActivity
```

Increment:

```bash
adb -s emulator-5554 shell am start \
  --activity-single-top \
  -n com.example.androidcookbook.fixture/.MainActivity \
  --es cookbook_action increment
```

Rotate:

```bash
adb -s emulator-5554 shell settings put system accelerometer_rotation 0
adb -s emulator-5554 shell settings put system user_rotation 1
```

Observe:

```bash
adb -s emulator-5554 logcat -d \
  -s CookbookLifecycle:I CookbookState:I '*:S'
```

Restore the original rotation settings after the exercise.

## Expected Behavior

Before rotation:

```text
instance=A
counter=5
orientation=portrait
```

During rotation:

```text
onSaveInstanceState
onDestroy
```

After rotation:

```text
instance=B
counter=5
orientation=landscape
restored=true
```

The new Activity instance ID must differ from the original.

## Testing Strategy

### Unit Tests

Verify:

- State log parsing
- State restoration invariants
- Rotation command construction
- Rotation settings capture and restoration
- Polling and timeout behavior

```bash
pytest tests/unit/test_activity_recreation.py -v
```

### Integration Tests

Verify on a dedicated Emulator:

- Activity launches in portrait
- Counter increments
- Rotation triggers recreation
- Old Activity saves state
- New Activity restores state
- Activity instance ID changes
- Package remains installed
- Rotation settings are restored during cleanup

```bash
export ANDROID_SERIAL=emulator-5554

pytest \
  tests/integration/test_activity_recreation.py \
  -m "integration and destructive" \
  -v
```

## Cleanup Policy

Tests must restore:

1. Original system rotation settings
2. Original fixture package absence
3. Test-controlled application state

Do not run tests that modify global device settings on shared or production devices.

## Limitations

- `onDestroy()` is not guaranteed for process death.
- Rotation may not trigger recreation on every device.
- Activity state restoration does not imply process recreation.
- `savedInstanceState` is not persistent storage.
- Logcat is not a durable event database.
- Tests assume exclusive control of a dedicated Emulator.
- Exact lifecycle callback ordering may vary across Android versions.
