# Start activities and inspect processes (v0.5.0)

Use Activity Manager to launch the fixture Activity, find its process, force-stop the
app, and restart it. Package Manager tracks installation; Activity Manager starts
components and manages running applications. An installed package can have no running
process, and an Activity is a component with its own lifecycle rather than a process.

## Before you begin

Follow [environment setup](../environment.md) and [build the test APK](v0.4.2-test-apk-fixture.md#build-the-test-apk).
Use a dedicated emulator running API 31 or later. The fixture package is
`com.example.androidcookbook.fixture`; its exported launcher Activity is `.MainActivity`.
It displays “Android Cookbook Activity Fixture”. Run commands from the repository root.

```bash
export ANDROID_SERIAL=emulator-5554
adb -s "$ANDROID_SERIAL" get-state
adb -s "$ANDROID_SERIAL" shell getprop sys.boot_completed
./scripts/build-test-apk.sh
```

Replace the serial with your emulator's serial. Expected responses are `device` and `1`.

## 1. Install and launch the fixture

```bash
adb -s "$ANDROID_SERIAL" install -r -t \
  tests/fixtures/test-app/cookbook-test-app.apk
adb -s "$ANDROID_SERIAL" shell pm list packages com.example.androidcookbook.fixture
adb -s "$ANDROID_SERIAL" shell am start -W \
  -n com.example.androidcookbook.fixture/.MainActivity
```

Installation reports `Success`; the package query includes
`package:com.example.androidcookbook.fixture`. Example launch output:

```text
Starting: Intent { cmp=com.example.androidcookbook.fixture/.MainActivity }
Status: ok
LaunchState: COLD
Activity: com.example.androidcookbook.fixture/.MainActivity
TotalTime: 352
WaitTime: 365
Complete
```

Fields and timings vary by device and Android version. `-W` waits for the launch result;
it does not prove UI rendering or asynchronous application work has completed.

## 2. Inspect and stop the process

```bash
adb -s "$ANDROID_SERIAL" shell pidof com.example.androidcookbook.fixture
adb -s "$ANDROID_SERIAL" shell am force-stop com.example.androidcookbook.fixture
adb -s "$ANDROID_SERIAL" shell pidof com.example.androidcookbook.fixture
adb -s "$ANDROID_SERIAL" shell pm list packages com.example.androidcookbook.fixture
```

Before force-stop, `pidof` returns one or more PIDs, such as `12345`. Afterward it normally
prints nothing and exits nonzero. The package query still reports the installed package.
Process lookup uses the exact process name; it does not enumerate differently named
processes such as `com.example.androidcookbook.fixture:remote`.

## 3. Restart and collect diagnostics

```bash
adb -s "$ANDROID_SERIAL" shell am start -S -W \
  -n com.example.androidcookbook.fixture/.MainActivity
adb -s "$ANDROID_SERIAL" shell dumpsys activity activities
```

`-S` force-stops the target app before starting the Activity. The dump describes current
tasks and Activities. Its format depends on Android version; the integration test checks
only that the output is non-empty.

Remove the manual installation before running tests, which require the package to be absent:

```bash
adb -s "$ANDROID_SERIAL" uninstall com.example.androidcookbook.fixture
```

## 4. Use the Python helpers

Run this example after installing the fixture, in a Python session started with
`PYTHONPATH=src poetry run python`:

```python
from android_cookbook.activity_manager import (
    force_stop_package,
    get_activity_dump,
    get_process_ids,
    is_process_running,
    start_activity,
)

serial = "emulator-5554"
package = "com.example.androidcookbook.fixture"
result = start_activity(
    serial, package, ".MainActivity", force_stop_before_start=True
)
print(result.status)           # ok
print(get_process_ids(serial, package))  # Example: [12345]
print(is_process_running(serial, package))
print(get_activity_dump(serial))
force_stop_package(serial, package)
```

There is no Activity Manager CLI or JSON entry point. Every helper takes an explicit serial.

| Helper | Return value |
| --- | --- |
| `make_component(package_name, activity_name)` | Component string such as `com.example.androidcookbook.fixture/.MainActivity` |
| `start_activity(serial, package_name, activity_name, *, force_stop_before_start=False)` | Frozen `ActivityStartResult` |
| `force_stop_package(serial, package_name)` | `None` after a successful command |
| `get_process_ids(serial, package_name)` | List of integer PIDs, or `[]` when absent |
| `is_process_running(serial, package_name)` | Boolean based on the PID list |
| `get_activity_dump(serial)` | Raw diagnostic stdout |

`ActivityStartResult` contains `component`, `success`, `status`, `launch_state`,
`total_time_ms`, `wait_time_ms`, and combined command `output`. Missing text fields are
`None`; missing or non-integer timings are also `None`. The standalone
`parse_activity_start_output(component, output, *, returncode=0)` helper parses without ADB.
Launch success requires exit code zero, `Status: ok`, and no line matching the parser's
`Error:` or `Exception occured` prefixes (the latter is the current spelling in code).
A failed launch raises `ActivityManagerError` instead of returning an unsuccessful result.

Blank serials and rejected package/component names raise `ValueError`. Current validation
accepts `.MainActivity` but rejects fully qualified or nested relative activity names.
The trailing-character regex uses `0-0` rather than `0-9` in activity names and package
segments after the first, so digits 1–9 there are rejected. This is a current implementation
limitation. A missing ADB executable raises `FileNotFoundError`.

Force-stop and diagnostic command failures raise `ActivityManagerError`. PID lookup returns
`[]` for a nonzero exit only when both stdout and stderr are empty; otherwise it raises.
Non-integer PID output also raises. Commands have no timeout.

## 5. Run the tests

```bash
PYTHONPATH=src poetry run pytest tests/unit/test_activity_manager.py -v

export ANDROID_SERIAL=emulator-5554
PYTHONPATH=src poetry run pytest tests/integration/test_activity_manager.py \
  -m "integration and destructive" -v
```

`pytest.ini` excludes destructive tests by default. The explicit marker expression opts in.
The shared `android_serial` fixture skips if `ANDROID_SERIAL` is unset, does not start with
`emulator-`, or fails the ADB `get-state` check. It does not auto-select a device.
The APK fixture skips if the file is missing; it does not validate APK contents.

Unit tests replace command execution and cover component validation, launch parsing with
and without optional fields, `-S` construction, launch/force-stop failures, PID presence,
absence and command errors, Boolean process lookup, and diagnostic output.

The five integration tests check launch success, process creation, force-stop without
uninstallation, restart with `-S`, and non-empty diagnostics. Process checks poll every
0.2 seconds for up to 10 seconds. They do not measure startup performance or validate
Activity lifecycle callbacks, UI rendering, foreground visibility, or service behavior.

Each test requires the fixture package to be absent. Setup fails if it is already installed,
then installs it with `-t`. Function-scoped cleanup attempts force-stop and uninstall in
nested `finally` blocks, so uninstall is attempted even when force-stop fails. Cleanup
failures remain visible. The serial and APK fixtures are session-scoped.
