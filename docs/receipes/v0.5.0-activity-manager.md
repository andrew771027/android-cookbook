# Android Cookbook v0.5.0 — Activity Manager

## Overview

Learn how Android starts Activities, manages application processes, and handles application force-stop operations.

This version builds on:

- v0.1 — ADB Basics
- v0.2 — ADB Shell
- v0.3 — Android Properties
- v0.4 — Package Manager
- v0.4.1 — Package Lifecycle Integration
- v0.4.2 — Test APK Fixture

## Learning Objectives

Understand the differences between:

- APK: an Android application package artifact
- Package: an installed application identity
- Activity: an Android application component with its own lifecycle
- Process: an operating-system process executing application code

Understand that an installed package does not necessarily have a running process, and an Activity is not equivalent to a process.

## Architecture

```text
Host Workstation
      |
      | adb
      v
Android Device / Emulator
      |
      +-- Package Manager
      |       |
      |       +-- Installed APK
      |
      +-- Activity Manager
              |
              +-- Activity Launch
              +-- Task Management
              +-- Application Process
              +-- Force-stop
```

## Prerequisites

Android Environment v0.4.x must provide a working Android Emulator.

Verify:

```bash
adb devices
adb -s emulator-5554 shell getprop sys.boot_completed
```

Expected boot property:

```text
1
```

Build the updated Activity fixture:

```bash
./scripts/build-test-apk.sh
```

## Manual Exercise 1 — Install Fixture

```bash
adb -s emulator-5554 install \
  tests/fixtures/cookbook-test-app.apk
```

Verify the package:

```bash
adb -s emulator-5554 shell pm list packages \
  com.example.androidcookbook.fixture
```

## Manual Exercise 2 — Launch Activity

```bash
adb -s emulator-5554 shell am start -W \
  -n com.example.androidcookbook.fixture/.MainActivity
```

Inspect the output:

- Status
- LaunchState, if present
- TotalTime, if present
- WaitTime, if present

A successful Activity launch does not guarantee that every asynchronous application operation has completed.

## Manual Exercise 3 — Inspect Process

```bash
adb -s emulator-5554 shell pidof \
  com.example.androidcookbook.fixture
```

The returned number is a process ID (PID).

If no matching process exists, `pidof` may produce no output and a nonzero exit code.

## Manual Exercise 4 — Force-stop

```bash
adb -s emulator-5554 shell am force-stop \
  com.example.androidcookbook.fixture
```

Verify the process is no longer running:

```bash
adb -s emulator-5554 shell pidof \
  com.example.androidcookbook.fixture
```

Verify that the package remains installed:

```bash
adb -s emulator-5554 shell pm list packages \
  com.example.androidcookbook.fixture
```

## Manual Exercise 5 — Restart

```bash
adb -s emulator-5554 shell am start -S -W \
  -n com.example.androidcookbook.fixture/.MainActivity
```

`-S` force-stops the target application before starting the Activity.

## Manual Exercise 6 — Activity Diagnostics

```bash
adb -s emulator-5554 shell dumpsys activity activities
```

Inspect the Activity Manager's current task and Activity state.

The output is diagnostic and Android-version-dependent. Avoid writing brittle tests that depend on exact internal formatting.

## Testing

Unit tests:

```bash
pytest tests/unit/test_activity_manager.py -v
```

Integration tests:

```bash
export ANDROID_SERIAL=emulator-5554

pytest \
  tests/integration/test_activity_manager.py \
  -m "integration and destructive" \
  -v
```

Integration tests must use a dedicated emulator and a disposable APK fixture.

Do not run destructive tests against system packages or personal devices.

## Test Lifecycle

```text
Fixture APK
     |
     v
Install Package
     |
     v
Start Activity
     |
     v
Verify Process Running
     |
     v
Force-stop Package
     |
     v
Verify Process Stopped
     |
     v
Verify Package Still Installed
     |
     v
Uninstall Fixture
```

## Cleanup Policy

Every destructive integration test must attempt to restore the emulator to its initial package state.

Use pytest fixtures with `yield` and `finally`.

Cleanup failures must be visible rather than silently ignored.

## Limitations

This version does not validate:

- Activity lifecycle callback order
- UI rendering completion
- application foreground visibility across every Android version
- background service lifecycle
- all application process names
- Activity startup performance benchmarks

These topics require additional instrumentation or more advanced Android APIs.

## Definition of Done

- [ ] Force-stop does not uninstall the package

- [ ] Integration tests pass on the dedicated emulator
- [ ] Fixture cleanup succeeds
- [ ] Documentation is complete
