# v0.3: Android properties

Read device properties with `getprop`, parse the output in Python, and print a device report
as JSON. The Python helpers use the [ADB shell wrapper](v0.2-adb-shell.md).

## Prerequisites

Complete the [environment setup](../environment.md), run `poetry install`, and confirm an
online device with `adb devices -l`. Replace `emulator-5554` below with your device serial.
Run Python examples in the Poetry environment with `PYTHONPATH=src`.

## Common properties

Use these properties to identify the product, Android release, installed build, and hardware.
The commands below assume one connected device. With multiple devices, use
`adb -s <serial> shell getprop <name>`. Values vary by device and build; an unset property
can produce empty output.

### Device identity

Device identity describes the product model and its internal product/device names. These
values help label test results; they are shared by devices of the same product and do not
identify an individual unit. The field meanings follow Android's
[Build API](https://developer.android.com/reference/android/os/Build).

```bash
adb shell getprop ro.product.model
adb shell getprop ro.product.manufacturer
adb shell getprop ro.product.name
adb shell getprop ro.product.device
```

| Property | Meaning | Collected field |
| --- | --- | --- |
| `ro.product.model` | User-facing model name. | `model` |
| `ro.product.manufacturer` | Product/hardware manufacturer. | `manufacturer` |
| `ro.product.name` | Overall product name used by the build. | `product` |
| `ro.product.device` | Internal device design name, often a codename. | `device` |

### Android version

Version properties describe the software release and API level. The release string is useful
for display; the SDK level identifies the Android API version. The security patch value is
the build's reported patch level in `YYYY-MM-DD` form. See
[Build.VERSION](https://developer.android.com/reference/android/os/Build.VERSION).

```bash
adb shell getprop ro.build.version.release
adb shell getprop ro.build.version.sdk
adb shell getprop ro.build.version.security_patch
```

| Property | Meaning | Collected field |
| --- | --- | --- |
| `ro.build.version.release` | User-visible Android release, such as `16`. | `android_version` |
| `ro.build.version.sdk` | API level, such as `36`; `getprop` returns text. | `sdk_level`, converted to `int` |
| `ro.build.version.security_patch` | Reported security patch date. | Not collected |

### Build information

Build properties help distinguish software images when investigating a failure. A fingerprint
identifies a build, not an individual device; treat it as an opaque string. Build type commonly
uses `user`, `userdebug`, or `eng`, and tags may include `release-keys` or `test-keys`. See
[Build.ID, FINGERPRINT, TYPE, and TAGS](https://developer.android.com/reference/android/os/Build).

```bash
adb shell getprop ro.build.id
adb shell getprop ro.build.fingerprint
adb shell getprop ro.build.type
adb shell getprop ro.build.tags
```

| Property | Meaning | Collected field |
| --- | --- | --- |
| `ro.build.id` | Build label or identifier. | `build_id` |
| `ro.build.fingerprint` | Full build identification string. | `build_fingerprint` |
| `ro.build.type` | Build variant: production (`user`), debugging (`userdebug`), or engineering (`eng`). | Not collected |
| `ro.build.tags` | Comma-separated build tags, including signing-related labels. | Not collected |

### Hardware

Hardware properties describe the board, hardware name, system-on-chip (SoC), and supported
application binary interfaces (ABIs). An ABI defines how native compiled code runs on the
platform. The ABI list describes software support and is useful when choosing native libraries.
The property mappings are defined in
[AOSP Build.java](https://android.googlesource.com/platform/frameworks/base/+/master/core/java/android/os/Build.java).

```bash
adb shell getprop ro.hardware
adb shell getprop ro.product.board
adb shell getprop ro.soc.manufacturer
adb shell getprop ro.soc.model
adb shell getprop ro.product.cpu.abilist
adb shell getprop ro.product.cpu.abilist32
adb shell getprop ro.product.cpu.abilist64
```

| Property | Meaning |
| --- | --- |
| `ro.hardware` | Hardware name reported by the platform; may be an internal name. |
| `ro.product.board` | Underlying board name. |
| `ro.soc.manufacturer` | Manufacturer of the primary SoC. |
| `ro.soc.model` | Model of the primary SoC. |
| `ro.product.cpu.abilist` | Supported ABIs in preference order, separated by commas. |
| `ro.product.cpu.abilist32` | Supported 32-bit ABIs. |
| `ro.product.cpu.abilist64` | Supported 64-bit ABIs. |

An ABI list might contain `arm64-v8a` or `x86_64`. A device without 32-bit application support
can have an empty `abilist32`. SoC properties may be unset on older or vendor-specific builds.
The SoC property definitions are also documented in
[AOSP SocProperties.sysprop](https://android.googlesource.com/platform/system/libsysprop/+/refs/heads/master/srcs/android/sysprop/SocProperties.sysprop).

The current `DeviceProperties` dataclass collects the eight fields marked above. Security
patch, build type/tags, and hardware properties can be read with `get_property()` or included
in the listing from `get_all_properties()`, but are not included in `device_info` JSON.

## 1. Read one property

```bash
adb -s emulator-5554 shell getprop ro.product.model
adb -s emulator-5554 shell getprop ro.build.version.sdk
```

To read a property from Python, import `get_property()` from `properties.py`:

```python
from android_cookbook.properties import get_property

model = get_property("emulator-5554", "ro.product.model")
sdk = get_property("emulator-5554", "ro.build.version.sdk")
```

Both results are strings with surrounding whitespace removed. An empty response stays empty.
This function calls `run_shell()` with `getprop` and the property name.

## 2. Parse all properties

```bash
adb -s emulator-5554 shell getprop
```

The parser expects lines shaped like `[name]: [value]`:

```python
from android_cookbook.properties import AndroidProperty, parse_properties

properties = parse_properties("""
[ro.product.model]: [Pixel 10]
[some.property]: []
invalid property line
""")

assert properties == [
    AndroidProperty(name="ro.product.model", value="Pixel 10"),
    AndroidProperty(name="some.property", value=""),
]
```

Each result is an `AndroidProperty` with `name` and `value` fields that cannot be reassigned.
The parser removes surrounding whitespace from each line, skips blank or unrecognized lines,
and keeps accepted entries in order. Duplicate names remain separate entries.

The parser only checks for a leading `[` and the separator `]: [`. It accepts empty values
and even a missing closing bracket. See [Property parsing](../architecture.md#property-parsing)
for the exact rules.

To read and parse a device listing in one ADB call:

```python
from android_cookbook.properties import get_all_properties

properties = get_all_properties("emulator-5554")
for prop in properties:
    print(f"{prop.name}={prop.value}")
```

## 3. Collect typed device information

```python
from dataclasses import asdict
from android_cookbook.properties import collect_device_properties

info = collect_device_properties("emulator-5554")
print(info.model)
print(info.sdk_level)  # int
print(asdict(info))
```

`DeviceProperties` contains the eight fields listed in the property tables above.
Its fields cannot be reassigned. All values are strings except `sdk_level`, which is an integer.

The collector reads each property in a separate ADB call. If the SDK response is empty or
cannot be converted with `int()`, collection raises `ValueError`.

## 4. Print JSON

```bash
PYTHONPATH=src poetry run python -m android_cookbook.device_info
```

`main()` selects the first device in state `device`, calls `collect_device_properties()`,
converts it with `asdict()`, adds the serial, and prints indented JSON. Example values:

```json
{
  "serial": "emulator-5554",
  "model": "Pixel 10",
  "manufacturer": "Google",
  "product": "example_product",
  "device": "example_device",
  "android_version": "16",
  "sdk_level": 36,
  "build_id": "TEST123",
  "build_fingerprint": "google/example/example:16/TEST123/user/release-keys"
}
```

Actual values depend on the device. No online device causes
`RuntimeError("No Android device available")`.

For the earlier helper that returns `sdk` and `build`, see
[v0.1 device information](v0.1-adb-basics.md#5-collect-device-information).

## 5. Run the tests

```bash
# No device required
PYTHONPATH=src poetry run pytest tests/unit/test_properties.py -v

# Requires ADB and an online device
PYTHONPATH=src poetry run pytest tests/integration/test_properties.py -m integration -v
```

Unit tests check line parsing, empty values, command arguments, output trimming, and
collection of all eight fields. They replace device calls with sample responses.

Integration tests read the model, SDK, Android version, full property listing, and collected
report from the first online device. They skip if none is connected. Missing ADB or failed
commands cause errors. For coverage gaps, see [Tests](../architecture.md#tests).

## Troubleshooting

- `ModuleNotFoundError: android_cookbook`: run from the repository root with `PYTHONPATH=src`
  as shown above, or install the project into the active environment.
- Skipped integration tests: check `adb devices -l`; `offline` and `unauthorized` devices
  are not selected.
- `ValueError` during collection: inspect `adb -s <serial> shell getprop ro.build.version.sdk`.
  The collector requires output accepted by `int()`.
- `CalledProcessError`: the underlying ADB command returned a non-zero status. Run it directly
  to inspect its error output. A missing ADB executable raises `FileNotFoundError`.
