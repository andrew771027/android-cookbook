# v0.1: ADB basics

Use `adb` from Python to find a connected device and read its system properties.
The examples use the functions in `src/android_cookbook/adb.py`.

## Prerequisites

Complete the [environment setup](../environment.md), then verify that one device is online:

```bash
adb devices -l
```

The state in the second column must be `device`. `offline` and `unauthorized` entries are visible
to the parser but are not selected by the device-info command.

## 1. Run ADB commands

List devices:

```bash
adb devices
```

Read a property from a particular device:

```bash
adb -s emulator-5554 shell getprop ro.product.model
adb -s emulator-5554 shell getprop ro.build.version.release
adb -s emulator-5554 shell getprop ro.build.version.sdk
adb -s emulator-5554 shell getprop ro.build.id
```

Replace `emulator-5554` with the serial shown by `adb devices`.

## 2. Execute ADB from Python

`run_adb()` starts the ADB process and returns its output:

```python
command = ["adb", *args]
result = subprocess.run(command, capture_output=True, text=True, check=True)
return result.stdout.strip()
```

Arguments are passed as a list rather than a shell command string. Output is returned as text and
outer whitespace is removed. Failed commands raise `subprocess.CalledProcessError`.

## 3. Parse connected devices

`list_devices()` ignores the `List of devices attached` header, empty rows, and rows with fewer
than two columns. Each valid row becomes an immutable `AdbDevice`:

```python
AdbDevice(serial="emulator-5554", state="device")
```

## 4. Read one Android property

`get_property()` turns this call:

```python
get_property("emulator-5554", "ro.product.model")
```

into this argument list:

```python
[
    "adb",
    "-s",
    "emulator-5554",
    "shell",
    "getprop",
    "ro.product.model",
]
```

Using `-s` prevents ambiguous behavior when more than one device is attached.

## 5. Collect device information

The original `collect_device_info()` helper reads four properties and adds the device serial:

```python
from android_cookbook.device_info import collect_device_info

info = collect_device_info("emulator-5554")
print(info)
```

It returns string values for `serial`, `model`, `android_version`, `sdk`, and `build`.

To print the current device report as JSON, run:

```bash
PYTHONPATH=src poetry run python -m android_cookbook.device_info
```

This command selects the first online device. It now uses the v0.3 property collector, which
adds more fields and converts the SDK level to an integer. See the
[current JSON example](v0.3-properties.md#4-print-json).
If no device is online, the command raises `RuntimeError: No Android device available`.

## 6. Run the tests

The test commands in this recipe are targeted development checks. Before every
commit, follow the [full commit verification procedure](../../CommitManual.md#run-the-full-integration-suite):
rebuild the APK, run all unit tests and the entire integration suite (including
destructive tests), and require every test to pass without skips or deselection.
Use only a dedicated online emulator and run sequentially.

The unit tests replace `subprocess.run`, allowing parsing and command construction to be checked
without invoking ADB:

```bash
PYTHONPATH=src poetry run pytest tests/unit/test_adb.py -v
```

The integration tests invoke real Android tooling:

```bash
export ANDROID_SERIAL=emulator-5554
PYTHONPATH=src poetry run pytest tests/integration/test_device.py -m integration -v
```

Unit tests check device parsing, offline states, and the arguments used to read a property.
The discovery test checks for any online device. The SDK test uses `ANDROID_SERIAL`
and skips unless it selects an online `emulator-*` device.

## Troubleshooting

### `adb: command not found`

Add the Android SDK `platform-tools` directory to `PATH`, then open a new terminal.

### Device is `unauthorized`

Unlock the device, accept the USB debugging prompt, and run `adb devices -l` again.

### Device is `offline`

Reconnect it or restart ADB:

```bash
adb kill-server
adb start-server
adb devices -l
```

### More than one device is connected

The property helper supports explicit serials, but `device_info.main()` currently selects the
first online device. Disconnect extra devices or call `get_property()` with the intended serial.
