# v0.1 Recipe: ADB Basics

This recipe demonstrates the first end-to-end feature in Android Cookbook: discover an online
Android device and print a few system properties as JSON.

## Goal

By the end of the recipe, the project can:

- execute `adb` from Python;
- list emulator and physical-device serials;
- retain each device's ADB connection state;
- target one device with `adb -s`;
- read Android properties with `getprop`; and
- present basic device information as JSON.

## Prerequisites

Complete the [environment setup](../environment.md), then verify that one device is online:

```bash
adb devices -l
```

The state in the second column must be `device`. `offline` and `unauthorized` entries are visible
to the parser but are not eligible for the device-info workflow.

## 1. Understand the underlying commands

List devices:

```bash
adb devices
```

Read a property from a particular device:

```bash
adb -s emulator-5554 shell getprop ro.product.model
adb -s emulator-5554 shell getprop ro.build.version.release
adb -s emulator-5554 shell getprop ro.build.version.sdk
adb -s emulator-5554 shell getprop ro.build.id
```

Replace `emulator-5554` with the serial shown by `adb devices`.

## 2. Execute ADB from Python

`run_adb()` in `src/android_cookbook/adb.py` centralizes process execution:

```python
command = ["adb", *args]
result = subprocess.run(command, capture_output=True, text=True, check=True)
return result.stdout.strip()
```

Arguments are passed as a list rather than a shell command string. Output is returned as text and
outer whitespace is removed. Failed commands raise `subprocess.CalledProcessError`.

## 3. Parse connected devices

`list_devices()` ignores the `List of devices attached` header, empty rows, and rows with fewer
than two columns. Each valid row becomes an immutable `AdbDevice`:

```python
AdbDevice(serial="emulator-5554", state="device")
```

## 4. Read one Android property

`get_property()` turns this call:

```python
get_property("emulator-5554", "ro.product.model")
```

into this argument vector:

```python
[
    "adb",
    "-s",
    "emulator-5554",
    "shell",
    "getprop",
    "ro.product.model",
]
```

Using `-s` prevents ambiguous behavior when more than one device is attached.

## 5. Collect and print device information

Run the application from the repository root:

```bash
PYTHONPATH=src poetry run python -m android_cookbook.device_info
```

The program uses the first entry whose state equals `device` and prints output similar to:

```json
{
  "serial": "emulator-5554",
  "model": "Pixel 10",
  "android_version": "16",
  "sdk": "36",
  "build": "BP2A.250705.008"
}
```

If no device is online, it raises `RuntimeError: No Android device available`.

## 6. Test the ADB boundary

The unit tests replace `subprocess.run`, allowing parsing and command construction to be checked
without invoking ADB:

```bash
poetry run pytest tests/unit/test_adb.py -v
```

The integration tests invoke real Android tooling:

```bash
poetry run pytest tests/integration/test_device.py -m integration -v
```

At the current development checkpoint, the tests do not yet match the implementation in every
case:

- `list_devices()` returns `AdbDevice` instances, while unit-test expectations use dictionaries
  with a `name` key.
- One mocked `get_property` test attempts to call the `subprocess` module instead of constructing
  `subprocess.CompletedProcess`.
- One integration test checks the misspelled state value `deivce`.

Treat those failures as contract work still to be resolved, not as ADB environment failures.

## Troubleshooting

### `adb: command not found`

Add the Android SDK `platform-tools` directory to `PATH`, then open a new terminal.

### Device is `unauthorized`

Unlock the device, accept the USB debugging prompt, and run `adb devices -l` again.

### Device is `offline`

Reconnect it or restart ADB:

```bash
adb kill-server
adb start-server
adb devices -l
```

### More than one device is connected

The property helper supports explicit serials, but `device_info.main()` currently selects the
first online device. Disconnect extra devices or call `get_property()` with the intended serial.
