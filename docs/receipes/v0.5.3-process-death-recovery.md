# v0.5.3: Recover state after process death

Background the fixture, request process termination, and verify that relaunching its
saved task restores counter 5 in a new process and Activity instance. This recipe uses
[`process_recovery.py`](../../src/android_cookbook/process_recovery.py) and builds on
[Activity recreation](v0.5.2-activity-recreation.md). v0.5.3 also fixes that recipe's
[rotation setup](v0.5.2-activity-recreation.md#v053-rotation-fix-root-cause-and-solution).

## Before you begin

Follow [Environment setup](../environment.md). Use an unlocked, dedicated emulator
running API 31 or later, with no other tests or automation using it. Run from the
repository root:

```bash
poetry install
./scripts/build-test-apk.sh
export ANDROID_SERIAL=emulator-5554
adb devices -l
adb -s "$ANDROID_SERIAL" get-state
adb -s "$ANDROID_SERIAL" shell pm list packages com.example.androidcookbook.fixture
```

The emulator must report `device`. Shared fixtures fail if the disposable package is
already installed. Remove a leftover manual installation before testing:

```bash
adb -s "$ANDROID_SERIAL" uninstall com.example.androidcookbook.fixture
```

Rebuild the APK even if an older copy already exists. The v0.5.3 fixture appends
`pid=<number>` to state logs; the process parser requires it. The APK is generated at
`tests/fixtures/test-app/cookbook-test-app.apk` and is ignored by Git. Its version is
0.5.3, but the state marker remains `android-cookbook-v0.5.2` and the lifecycle marker
remains `android-cookbook-v0.5.1`.

## Compare the scenarios

| Scenario | What the tests verify |
| --- | --- |
| Rotation | New Activity UUID, restored counter, changed orientation, and per-instance callbacks; the rotation tests do not assert PID continuity |
| Background process death | Original process absent; after relaunch, new PID and UUID, `created` with restored state, and unchanged counter |
| Force-stop | Process absent and package still installed; no assertion that the saved Bundle survives |

Process death does not guarantee `onDestroy()`. `savedInstanceState` holds transient
UI state, not durable application data. Force-stop is not a substitute for ordinary
background process death.

## Run the recovery exercise

```bash
PYTHONPATH=src poetry run pytest tests/integration/test_process_recovery.py \
  -m "integration and destructive" -v -rs
```

[`prepare_background_app()`](../../tests/integration/test_process_recovery.py) performs
these steps:

1. Force-stop the fixture to start fresh, then launch using MAIN/LAUNCHER and task flags.
2. Wait for `created`, counter 0, and `restored=false`.
3. Send five `increment` actions, matching each result by instance UUID and counter.
4. Press Home and wait for that instance's `saved` event with counter 5.

The test then requests `am kill` and polls until the package has no process. If Android
still considers it important and the process remains after 10 seconds, the test skips.
A successful `am kill` command alone does not prove process death.

The recovery test relaunches the app using the same launcher intent. It waits for a
`created` event with a different PID and instance UUID. `evaluate_recovery()` checks
those identities and the event name; `assert_state_recovered()` separately requires
`restored=true` and equal counters. The test also verifies the package remains installed.

Equivalent commands for manual inspection after preparing the app state are:

```bash
adb -s "$ANDROID_SERIAL" shell input keyevent KEYCODE_HOME
adb -s "$ANDROID_SERIAL" shell am kill com.example.androidcookbook.fixture
adb -s "$ANDROID_SERIAL" shell pidof com.example.androidcookbook.fixture
# Continue only after confirming that the original process is absent.
adb -s "$ANDROID_SERIAL" shell am start -W \
  -a android.intent.action.MAIN -c android.intent.category.LAUNCHER \
  -f 0x10200000 -n com.example.androidcookbook.fixture/.MainActivity
adb -s "$ANDROID_SERIAL" logcat -d -s CookbookState:I '*:S'
```

Illustrative state logs (PIDs and UUIDs vary):

```text
CookbookState: marker=android-cookbook-v0.5.2 instance=11111111-1111-1111-1111-111111111111 event=saved counter=5 orientation=portrait restored=false pid=1234
CookbookState: marker=android-cookbook-v0.5.2 instance=22222222-2222-2222-2222-222222222222 event=created counter=5 orientation=portrait restored=true pid=5678
```

Only `created` reports whether `onCreate()` received a saved Bundle. Other events,
including `saved` and `resumed`, log `restored=false`.

## v0.5.3 fixes: root cause and solution

### State-event timeouts

The process log reader used the device serial as a Logcat tag filter, such as
`emulator-5554:I`, while the fixture emits `CookbookState`. The reader now filters
`CookbookState:I`; `test_read_process_state_events` checks the command and parsed result.

A second cause was a stale APK without the required `pid` field. Its logs could be
read but were rejected by `PROCESS_STATE_PATTERN`. Rebuild the fixture from the Java
source, which emits `Process.myPid()`. Increasing the polling timeout fixes neither
cause.

### Missing saved state after relaunch

The failing run created a new process and Activity, but reported counter 0 and
`restored=false`. The original setup used a component start while the recovery launch
used MAIN/LAUNCHER without the launcher task flags. The test did not consistently
establish and resume the same task through matching launcher intents.

Both launches now use `launch_from_launcher()` with MAIN, LAUNCHER, and
`0x10200000` (`NEW_TASK | RESET_TASK_IF_NEEDED`). The initial force-stop remains before
fresh setup; there is no force-stop between saving state and the recovery launch.
The unit test checks the launcher action, category, and flags. The integration test
still requires actual Bundle restoration and counter equality.

### Rotation baseline

The rotation failure occurred before any increment: only `created` and `resumed` in
landscape were observed while the test waited for portrait. Applying rotation before
launch did not reliably establish the Activity's initial orientation. v0.5.3 applies
`wm user-rotation lock 0` after launch, waits for a portrait `created` event, and then
increments. This setup may itself recreate the Activity, so its zero-counter baseline
allows `restored=true`. The later landscape transition still checks restored counter 5.
See the [full rotation diagnosis](v0.5.2-activity-recreation.md#v053-rotation-fix-root-cause-and-solution).

## Python helpers and limits

| Helper | Behavior |
| --- | --- |
| `parse_process_state_events(output)` | Parse ordered state fields ending in `pid` into frozen `ProcessStateEvent` objects |
| `read_process_state_events(serial)` | Read a `CookbookState:I` Logcat snapshot and parse it |
| `wait_until(predicate)` | Poll immediately, then every 0.2 seconds; return a Boolean, default timeout 10 seconds |
| `wait_for_process_absent(serial)` | Return whether the package has no process within the timeout |
| `wait_for_new_process(serial, old_pid)` | Return the first PID different from the old PID, or raise `LifecycleError`; not used by the integration recovery flow |
| `request_background_process_kill(serial)` | Request `am kill`; does not itself confirm termination |
| `launch_from_launcher(serial)` | Start MAIN/LAUNCHER with task flags and return command stdout |
| `wait_for_process_state_event(serial, predicate)` | Return the first matching snapshot event; default timeout 15 seconds, interval 0.2 seconds; raise `LifecycleError` on timeout |
| `evaluate_recovery(before, after)` | Require different PIDs and UUIDs and an after-event named `created`; return `RecoveryResult` |
| `assert_state_recovered(result)` | Require restored state and equal counters; raise `AssertionError` otherwise |

Polling rejects negative timeouts and nonpositive intervals. Logcat snapshots can
contain old events or lose entries; correlate by PID, instance UUID, and counter.
Individual lifecycle ADB calls have a 20-second timeout and can exceed a polling
deadline. PID values can eventually be reused. Task preservation and `am kill`
eligibility depend on Android's state. These helpers provide no CLI or persistent storage.

## Verify changes and cleanup

```bash
PYTHONPATH=src poetry run pytest tests/unit/test_process_recovery.py \
  tests/unit/test_activity_recreation.py -v
PYTHONPATH=src poetry run pytest tests/integration/test_process_recovery.py \
  tests/integration/test_activity_recreation.py -m "integration and destructive" -v -rs
```

Process unit tests cover parsing, the log tag filter, process absence and PID changes,
command arguments, and recovery assertion failures. Rotation unit tests cover command
construction, setting capture/restoration, parsing, polling, and restoration assertions.
Three process integration tests cover background death without uninstalling, saved state
recovery, and force-stop without uninstalling. Two rotation integration tests cover
counter restoration with callbacks and recreation without uninstalling.

The targeted fix verification passed 29 unit cases and all 5 integration cases,
including a run with the emulator initially locked in landscape. This was a targeted
check, not the complete release verification required by Commit Manual.

Shared fixtures force-stop and uninstall the app during teardown and report cleanup
failures. The rotation fixture captures both settings before the test and attempts
restoration in `finally`; it does not assert read-back values. Confirm package absence
and original rotation settings afterward.

Before committing, follow [Commit Manual](../../CommitManual.md#run-the-full-integration-suite):
rebuild the APK, leave only the dedicated emulator online, remove existing fixture
installations, then run the complete suites sequentially:

```bash
PYTHONPATH=src poetry run pytest tests/unit
PYTHONPATH=src poetry run pytest tests/integration -m integration -v -rs
git diff --check
```

Every test must pass with no errors, skips, or deselection, including cases where
`am kill` would otherwise skip. Default pytest and file-specific runs do not satisfy
this requirement. `make test_all_integration` includes the full integration suite;
`make test_integration` selects only destructive tests.
